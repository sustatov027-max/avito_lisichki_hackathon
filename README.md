# Сервис цепочек обмена товарами

Веб-сервис для многостороннего бартера. Пользователь указывает товар, который готов отдать, и требования к желаемому товару. Система сопоставляет предложения и автоматически находит замкнутые цепочки обмена из 2–5 участников: каждый участник отдаёт свой товар и получает подходящий ему товар другого пользователя.

## Возможности

- создание предложения с описанием, категорией, фотографиями, оценочной стоимостью и характеристиками товара;
- настройка требований к желаемому товару: категория, диапазон цены, характеристики и возможность доставки;
- автоматический поиск замкнутых цепочек обмена;
- просмотр своих предложений и найденных для них цепочек;
- наглядное отображение цепочки и товаров её участников;
- принятие или отклонение участия в цепочке каждым пользователем;
- светлая и тёмная темы с несколькими цветовыми вариантами;
- адаптивный пользовательский интерфейс;
- интерактивная документация REST API.

> В хакатонной версии полноценная авторизация заменена выбором тестового пользователя. Frontend передаёт его UUID в заголовке `X-User-ID`.

## Быстрый запуск

### Требования

- Docker с плагином Docker Compose;
- свободные порты `80`, `8080` и `5432`.

### Запуск через Docker Compose

1. Клонируйте репозиторий и перейдите в его каталог:

   ```bash
   git clone https://github.com/sustatov027-max/avito_lisichki_hackathon.git
   cd avito_lisichki_hackathon
   ```

2. При необходимости создайте локальный файл настроек:

   ```bash
   cp .env.example .env
   ```

   Этот шаг необязателен: для всех переменных в `docker-compose.yml` заданы значения по умолчанию.

3. Соберите и запустите приложение:

   ```bash
   docker compose up --build -d
   ```

   Compose запустит PostgreSQL, применит миграции и тестовые данные, соберёт backend и frontend.

4. Откройте сервисы:

   - приложение — <http://localhost>;
   - Swagger UI — <http://localhost:8080/swagger/index.html>;
   - проверка состояния backend — <http://localhost:8080/health>.

5. Для просмотра логов или остановки:

   ```bash
   docker compose logs -f
   docker compose down
   ```

Чтобы одновременно удалить локальный том с данными PostgreSQL и получить чистую базу при следующем запуске, используйте `docker compose down -v`.

### Запуск для разработки

Для запуска frontend и backend в Docker без HTTPS используйте отдельный dev-compose:

```bash
docker compose -f docker-compose.dev.yml up --build
```

После запуска приложение доступно по адресу <http://localhost>.
Nginx на 80-м порту раздаёт frontend и проксирует запросы `/api/` в backend-контейнер на `app:8080`.
Сам backend также доступен напрямую по адресу <http://localhost:8080>.
Остановка:

```bash
docker compose -f docker-compose.dev.yml down
```

Для frontend требуются Bun и Node.js-совместимое окружение, для backend — Go и PostgreSQL.

```bash
# Инфраструктура: PostgreSQL, миграции и тестовые данные
docker compose up -d postgres migrations seeds

# Backend (из отдельного терминала)
cd backend
cp ../.env.example .env
go run ./cmd/api

# Frontend (из отдельного терминала)
cd frontend
cp .env.example .env
# В .env укажите VITE_API_URL=http://localhost:8080/api/v1
bun install
bun run dev
```

Адрес dev-сервера Vite будет выведен в терминале. Запросы с `/api` проксируются на backend.

## Особенности реализации

### Поиск цепочек обмена

После создания предложения PostgreSQL-функция рекурсивно обходит граф совместимых товаров и ищет циклы длиной от 2 до 5. При сопоставлении учитываются:

- категория и допустимый диапазон стоимости;
- город либо взаимное согласие на доставку;
- строковые, булевы, списочные и диапазонные характеристики в JSONB;
- активность товара и уникальность товаров и пользователей в одной цепочке.

Поиск защищён транзакционной advisory-блокировкой, а уже найденные комбинации не создаются повторно. Новая цепочка доступна для решения 24 часа.

### Согласование обмена

Решение каждого участника хранится отдельно. Отклонение отменяет цепочку, а положительное решение всех участников переводит её в принятое состояние. Предусмотрена возможность изменить промежуточное решение до завершения процесса.

### Надёжность API

- создание предложения поддерживает заголовок `Idempotency-Key`, предотвращающий повторную обработку запроса;
- входящие тела запросов ограничены 2 МБ;
- DTO валидируются до передачи в бизнес-логику;
- сервер поддерживает graceful shutdown и таймауты HTTP;
- схема БД развивается последовательными reversible-миграциями;
- API доступен в формате OpenAPI и через Swagger UI.

### Клиентское приложение

Frontend содержит многошаговую форму создания предложения, кеширование серверных данных, обработку состояний загрузки и ошибок, визуальный граф цепочки, модальные карточки товаров, уведомления и переключение тем. Production-сборка раздаётся Nginx, который также проксирует `/api` на backend и поддерживает client-side routing.

## Основные API-маршруты

Все прикладные маршруты используют префикс `/api/v1` и работают от имени выбранного тестового пользователя. В таблице они приведены с полным префиксом.

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/api/v1/offers` | Создаёт новое предложение: товар пользователя и критерии желаемого товара. После сохранения запускается поиск подходящих цепочек обмена. |
| `GET` | `/api/v1/offers/my` | Возвращает все предложения текущего пользователя вместе с их актуальным состоянием и сведениями о найденных цепочках. |
| `GET` | `/api/v1/chains` | Возвращает список цепочек обмена, в которых участвует текущий пользователь. |
| `GET` | `/api/v1/chains/{chain_id}` | Возвращает выбранную цепочку целиком: последовательность участников, передаваемые товары и принятые решения. |
| `GET` | `/api/v1/chain/{chain_id}` | Альтернативный маршрут для получения одной цепочки; сохранён для совместимости. |
| `POST` | `/api/v1/chains/{chain_id}/decision` | Сохраняет решение текущего пользователя — принять предложенную цепочку или отказаться от участия. |
| `GET` | `/health` | Проверяет, что backend запущен и отвечает. Не требует выбора пользователя. |
| `GET` | `/swagger/index.html` | Открывает интерактивную документацию API. |

Для прикладных маршрутов frontend передаёт UUID пользователя в заголовке `X-User-ID`. При создании предложения также используется `Idempotency-Key`, чтобы случайно не создать один обмен несколько раз. Подробные форматы запросов и ответов доступны в Swagger UI.
