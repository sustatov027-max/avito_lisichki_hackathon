# Инструкции для Codex

## Стек проекта

- Node.js + React, TypeScript.

## Правила экономии токенов (Strict Limits)

1. Пиши код максимально кратко, без длинных текстовых объяснений, если я сам о них не попрошу.
2. Не генерируй заново весь файл, если изменения затрагивают только одну функцию. Выводи только измененный diff/фрагмент.
3. Не надо задавать компонентам focus-visible, я это уже сделал глобально
4. Не деструктурируй props const Example = (здесь) => { ... }, делай это const Example = (props) => {
   const {так} = props
   }
5. Когда пишешь стили используй все инструменты SCSS которые я сделал, они лежат в src/shared/styles, и в src/app/styles.
6. Не пиши в начале файла SCSS @use '@shared/styles/helpers' as *;
7. Если это компонент можно анимировать, то используй анимацию сдеражнно, и используй для этого framer-motion.
8. В shared/ui/index.ts файл не нужно экспортировать типы пропсов компонентов

## Правила SCSS

1. Используй вложенность SCSS через `&` для модификаторов и состояний компонента: `&.isActive`, `&:hover`, `&:disabled`.
2. Не дублируй полный селектор отдельно только ради модификатора. Модификаторы должны находиться внутри основного селектора компонента.
3. Вложенные элементы компонента пиши внутри родительского селектора: `.card { .title { ... } }`.
4. Миксины (`@include mobile`, `@include mobile-s`, `@include laptop`, `@include hover` и другие) подключай внутри селектора, к которому они относятся.
5. Не выноси `@include` в отдельный блок с повторением того же селектора. Пиши адаптивные и hover-стили внутри основного селектора.
6. Используй существующие SCSS-миксины из `src/shared/styles` и `src/app/styles`, не дублируй их логику вручную.
7. Для цветов, отступов, радиусов, границ, теней и длительности переходов используй CSS-переменные проекта: `var(--surface)`, `var(--text-primary)`, `var(--border)`, `var(--radius-md)`, `var(--duration)` и другие доступные переменные.
8. Не добавляй в начало SCSS-файла `@use '@shared/styles/helpers' as *;` — переменные и миксины уже подключаются глобально.
9. Для повторяющихся состояний объединяй селекторы внутри основного блока, например `&.isAccepted, &.isCompleted`.
10. Новые стили должны учитывать мобильную версию через соответствующий миксин, если компонент меняет размеры, направление или расположение на маленьком экране.
